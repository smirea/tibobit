# Gameplay

What the bot (`scripts/tibo-bot.ts`) learns from its runs.

- `strategy.md` is the game knowledge: what earlier runs taught, generalized. During a run the decision model, as the planner, reads it in full before every pick and every goal, so it is written as short plain rules. After each run the coach reads the run's CSV log (one row per model call, with the player's state; see the main README), notes and stats, names the moments that decided the run and what should have happened instead, and rewrites this file from them.
- `notes/` holds one dated file per run, made from `notes/TEMPLATE.md`. The run's share link goes at the top once the game shows the run summary, then every pick by game time, the outcome, and the post-run review with the moments that decided the run. The table names the run's CSV log in `/tmp/tibobit/`.
- `infrastructure_feedback.csv` collects the coach's suggestions about the bot itself: data the decision model lacks, missing commands, confusing descriptions. Columns: `date,run,time,notes`, where `time` is the game time the suggestion came from.
- `experiments.md` is the list of high-level strategies to try on experiment runs (greedy, safe, short-term or long-term focus, and whatever else the coach thinks worth testing), with each idea's status and what runs so far showed and why. Every third finished run is an experiment (`--experiment-every`, 0 turns it off; `--experiment <name>` forces one). At the end of every review the coach names the next experiment, with a hypothesis and a directive, in `next-experiment.json`; an experiment run copies it into its notes and plays that directive for the whole run even where `strategy.md` disagrees, so the strategy does not settle into a local maximum. The coach rewrites this list after every run.
- `experiments.csv` logs every experiment run: `date,run,experiment,hypothesis,survived,expected,unexpected,lesson`. The review judges an experiment on what it tested, not on survival alone, and only the lessons that held up go into `strategy.md`.
